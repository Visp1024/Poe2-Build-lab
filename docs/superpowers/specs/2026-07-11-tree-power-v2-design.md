# Дизайн: Node Power v2 — пул Lua-воркеров, шаги до ноды, редизайн панели

**Дата:** 2026-07-11
**Статус:** Одобрено (фаза дизайна)
**Область:** PBLEngine + PBLApp.Core + PBLApp (Tree-таб), IPC/MCP, локализация
**База:** ветка `feat/tree-node-power-heatmap` (v1: спека 2026-06-19), после вливания `main`

## Цель

Довести фичу «тепловая карта + Power Report» (v1 на ветке) до рабочего состояния:

1. **Скорость** — расчёт power распараллеливается на пул фоновых LuaHost-воркеров
   (сейчас: ~2 полных `calcFunc`-пересчёта × ~2000 нод на одном инстансе → минуты).
2. **Шаги до ноды** — колонка показывает чёткое «сколько очков потратить, чтобы
   взять ноду»; текущие числа неверны (для взятых нод — `#node.depends`, для
   кластерных — захардкоженная `1`, для остальных возможно stale-пути).
3. **Редизайн UI** — панель отчёта и управление переводятся в домашний стиль
   TraderWindow (карточки, канонические ComboBox, разгруженный тулбар).

Решения, зафиксированные в брейншторме:
- Воркеры создаются **лениво, при первом запуске расчёта тепловой карты** —
  не при загрузке билда. Пока фича не используется, память и CPU не тратятся.
  После первого расчёта пул живёт дальше (повторные расчёты быстрые).
- Модель пересчёта остаётся **ручной**: stale-бейдж + кнопка, без автопересчёта.
- Значения power считаются в целом верными — расчётную логику PoB не трогаем.
- Подход: **пул воркеров в процессе + ленивый pathPower** (топ-100), а не
  отдельные процессы и не только-оптимизации одного инстанса.

## Не-цели

- Автопересчёт после правок билда (остаётся ручной Refresh).
- Пересчёт pathPower для всех нод (только топ-100 по |power|; остальным «—»).
- Досчёт pathPower по требованию (скролл/клик) — YAGNI.
- Выбор цветовой темы карты (остаётся RED/BLUE константой).
- Изменение самой расчётной логики PoB (`CalcsTab:BuildPower` остаётся эталоном
  в паритет-тесте).

## Архитектура

### Компонент 1 — `LuaWorkerPool` (`PBLEngine`)

Новый класс, владеющий N дополнительными `LuaHost`-инстансами.

- **Размер пула**: по умолчанию `min(4, Environment.ProcessorCount - 2)`,
  настройка в Settings (`0` = пул выключен). Перед фиксацией дефолта замерить
  RSS на воркер: если > ~500 МБ — снизить дефолт до 2.
- **Прогрев (ленивый)**: воркеры создаются при **первом запуске расчёта**
  тепловой карты, инициализация параллельно со сдвигом (стаггером). Расчёт
  устроен как **очередь батчей**: каждый воркер по мере готовности подключается
  к очереди и начинает считать — первый готовый стартует, не дожидаясь
  остальных. В шапке панели на это время статус «прогрев воркеров: K/N».
  После расчёта пул не убивается — повторные запуски идут сразу параллельно.
  Статус (`WorkersReady/WorkersTotal`) публикуется наружу событием.
- **Синхронизация билда**: на каждый запуск расчёта — `SaveBuildToXml()` на
  главном хосте, затем параллельный `LoadBuildFromXml` на каждом готовом
  воркере. Воркеры — одноразовые считающие копии на время расчёта; источник
  правды всегда главный хост.
- **Обход**: главный хост (после флаша `_fastAllocDirty` через
  `BuildAllDependsAndPaths`) отдаёт список id невзятых нод + их `pathDist`.
  Список делится по готовым воркерам группами с одинаковым `modKey`
  (round-robin по группам) — иначе кэш по `modKey` теряет смысл, когда
  одинаковые малые ноды разлетаются по разным воркерам. Каждый воркер выполняет
  компактный Lua-цикл: батчи по ~25 нод, на ноду —
  `calcFunc({ addNodes = { [node] = true } })` с кэшем по `modKey` (как в PoB),
  между батчами возврат в C# (прогресс + проверка `CancellationToken`).
  Результат батча — плоская `\x1F`/`\t`-строка (id, power, offence, defence) —
  NLua long-list-safe, как в v1.
- **Слияние**: C# агрегирует строки всех воркеров, считает максимумы
  (`SingleStat`/`Offence`/`Defence`), строит отчёт и оверлей карты.
- **Ленивый pathPower**: после слияния топ-100 нод по |power| распределяются по
  воркерам для `calcFunc({ addNodes = pathNodes })`; из результата — колонка
  «за очко» (`pathPower / pathDist`). Остальные строки — «—».
- **Деградация**: готово K < N воркеров — очередь батчей естественно
  обслуживается теми, кто готов. Пул выключен (N = 0) или все воркеры мертвы —
  тот же цикл выполняется на главном хосте с периодическими yield'ами (единый
  код-путь, кнопка «Сгенерировать» работает всегда, просто медленнее).
- **Отмена**: токен; воркеры дорабатывают текущий батч и выходят; состояние Lua
  очищается (как в v1: восстановление `GetTime`, снятие временных глобалов).
- **Потоки**: каждый воркер — свой Lua-state на своём потоке; между собой не
  общаются; главный хост во время расчёта воркеров свободен для UI-запросов
  (ховеры, тултипы) — его семафор не занят чужими батчами.

### Компонент 2 — шаги до ноды

- **Семантика**: `Steps` = число невзятых нод в `node.path`, **включая саму
  ноду** = «сколько очков потратить, чтобы её взять».
- Считается **только на главном хосте** при формировании списка нод (после
  `BuildAllDependsAndPaths`) — тем же механизмом, что и ховер-инфо
  (`GetNodeHoverInfo.pathLen`), который показывает верные пути.
- Взятые ноды: `Steps = null` → в UI «—» (вместо `#node.depends`).
- Кластерные нотабли вне досягаемости пути: `Steps = null` → «—» (вместо `1`).
- Root-cause текущих неверных чисел — первой задачей плана через
  systematic-debugging (кандидаты: stale-пути из-за оптимистичной аллокации,
  снятие pathDist после прогона корутины v1).

### Компонент 3 — редизайн UI (`PBLApp`, стиль TraderWindow)

- **Тулбар дерева**: остаётся только кнопка-тоггл «Тепловая карта» (иконка,
  подсветка активного состояния). ComboBox стата, «Сгенерировать», прогресс —
  всё уезжает из тулбара в панель.
- **Панель отчёта** (справа, ресайз как в v1):
  - Шапка: ComboBox стата по каноническому рецепту (plain SukiUI, локализованный
    список + SelectedIndex, light-dismiss, MaxWidth), кнопка
    «Сгенерировать»/«Обновить», прогресс-бар, stale-бейдж, статус пула
    («воркеры: 2/4»).
  - Селектор сортировки: «по приросту / за очко» (как селектор сортировки
    результатов в трейдере). Сортировка «за очко» ранжирует топ-100 (у которых
    pathPower посчитан), остальные ниже по power.
  - Строки — двухстрочные карточки: (1) имя ноды + бейдж типа
    (нотабль/кистоун/обычная); (2) прирост стата (форматированный, цвет знака) +
    «за N очков» + значение за очко. Клик — фокус ноды на дереве (есть в v1),
    ховер — тултип ноды.
  - Фильтр по имени над списком.
- **Тепловая карта**: кривая `(max(power,0)/powerMax*1.5)^0.5` и RED/BLUE без
  изменений; деклаттер при отдалении — как в v1. Новое: кольца-акценты на
  топ-10 нодах по power, чтобы лучшие ноды находились взглядом.

### Компонент 4 — IPC / MCP / локализация

- IPC: `/tree/state` дополняется `workersReady`, `workersTotal`;
  `/tree/power-build`, `/tree/power-report` — интерфейс прежний, в отчёте новые
  поля (`steps` nullable, `perPoint` nullable).
- MCP: `visual_tree_power_build` / `visual_tree_power_report` без изменений
  сигнатур.
- Локализация RU/EN: бейджи типов, подписи сортировки, статус пула, «—»,
  «за N очков».

## Поток данных

1. Пользователь включает карту / жмёт «Сгенерировать» в панели. Первый запуск
   дополнительно стартует прогрев пула (статус «прогрев воркеров: K/N»).
2. Главный хост: флаш dirty → XML билда + список невзятых нод (id, pathDist,
   имя, тип) → очередь батчей.
3. Воркеры по мере готовности: загрузка XML → разбор батчей из очереди →
   плоские строки.
4. C#: слияние, максимумы, отчёт, оверлей → топ-100 → воркеры досчитывают
   pathPower → колонка «за очко» дозаполняется.
5. Правка билда → `IsPowerStale = true` (без автопересчёта).

## Обработка ошибок

- Ошибка/падение воркера при загрузке XML или в батче: его корзина
  доразбрасывается по живым воркерам; воркер помечается мёртвым и пересоздаётся
  в фоне; расчёт не падает целиком.
- Ошибка на всех воркерах → фолбэк на главный хост (код-путь деградации).
- `powerMax = 0` → карта не тонируется, отчёт с пометкой «нет измеримого
  изменения» (как в v1).
- Прогрев не завершён (в т.ч. первый запуск: готово 0 воркеров) → очередь
  ждёт первого готового воркера, остальные подключаются по мере прогрева;
  статус «прогрев воркеров: K/N» в шапке объясняет задержку.

## Тестирование

- **Паритет пула** (ключевой): на фикстурном билде результат пула (power по
  каждой ноде, максимумы) совпадает с прогоном оригинальной PoB-корутины
  `CalcsTab:BuildPower` на одном хосте в пределах допуска `1e-6`.
- Семантика шагов: `Steps` в отчёте == длине пути при клике на ту же ноду
  (сверка с `GetNodeHoverInfo`); взятые и недостижимые кластерные → null.
- Отмена: прерывание посреди расчёта оставляет чистое состояние (по образцу
  теста v1).
- Деградация: пул из 0 воркеров даёт тот же результат на главном хосте.
- Побочные эффекты: расчёт воркеров не меняет `mainOutput` главного хоста
  (стат-снимок до/после).
- Визуально: `/pbl-verify` — скриншоты панели (карточки, сортировка, статус
  пула) и карты (тонировка + кольца топ-10).

## Порядок работ

1. Влить `main` в `feat/tree-node-power-heatmap` (конфликты ожидаемы в
   `TreeTabView.axaml` / `TreeTabViewModel.cs`), убедиться что v1 собирается.
2. Root-cause и фикс шагов (systematic-debugging + тест).
3. `LuaWorkerPool` + деградация + паритет-тест.
4. Ленивый pathPower.
5. Редизайн панели и тулбара + кольца топ-10.
6. IPC/MCP/локализация, замер памяти → фиксация дефолта N, `/pbl-verify`.
