# PBLApp — переработка фирменного стиля: HTML-мокап

**Дата:** 2026-06-13
**Статус:** согласован, готов к плану реализации

## Цель

Сформировать единый фирменный стиль PBLApp и показать его в HTML-мокапе,
последовательно применённый к ключевым экранам: общая шапка, **Билды**,
**Предметы**, **Умения**, **Calcs**. Мокап — design-артефакт для согласования
визуального языка; production-UI остаётся на Avalonia/XAML.

## Решения (из брейнсторма)

- **Направление:** эволюция текущего стиля (тёмная нейтральная база + золотой
  PoE2-акцент), а не смена языка.
- **Формат:** Style Guide + экраны.
- **Два варианта** в одном файле с переключателем A / B:
  - **A — «На токенах»:** строго существующие design-токены, сразу портируется
    в Avalonia.
  - **B — «Свободный»:** смелее, можно вводить новые токены/контролы и заметные
    отклонения (вертикальный nav-rail одобрен).

## Пять принципов фирменного стиля (общие для A и B)

1. **Идентичность** — читаемый золотой вордмарк + «золотая нить»: золото
   используется только для бренда, активного состояния и главного действия, не
   размазано по интерфейсу.
2. **Иерархия шапки** — три явно разделённые зоны: идентичность билда ·
   стат-HUD · переключатель вкладок.
3. **Единый язык панелей** — одна карточка/панель (поверхность BgSurface,
   BorderSubtle, радиус Md, заголовок с цветовым кодом-акцентом) переиспользуется
   во всех экранах.
4. **Стат-HUD** — семантические чипы «лейбл + число» (моноцифры) вместо строки
   текста; цвет из `Stat*`-токенов.
5. **Состояния** — единые hover / selected / focus; house-style «боксированной
   ячейки-селектора» (BgSurface/BorderSubtle/radius6/h36) и Border-X удаления;
   активная строка — левый золотой бордюр.

## Содержимое мокапа (на реальном контенте из текущего клиента)

**Шапка (общая):** «← Назад», имя билда `Mercenary - Tactician (L62)`,
селекторы Класс/Восхождение, кнопки Заметки / Импорт-Экспорт / Язык /
Сохранить; стат-HUD: ДПС, Жизнь, ЭЩ, Мана, Броня, Укл, Дух; основной активный
скилл-селектор.

**Экран «Билды»:** заголовок «Билды», тулбар (сортировка/язык), сетка карточек с
артом класса + имя/восхождение/уровень, тайл «+ Создать билд».

**Экран «Предметы»:** paper-doll слотов (рамки по редкости), правая панель-
редактор (плейсхолдер «Выберите слот…» + «Создать предмет»), фласки, базовые
самоцветы, пул предметов.

**Экран «Умения»:** список групп слева (цвет по атрибуту гема, активная +
залоченные), панель деталей: имя активного скилла, Ур./Ка./Вкл., строки-
саппорты в стиле ComboBox с Border-X, строки «+ добавить саппорт»,
«+ Добавить умение».

**Экран «Calcs»:** три колонки (Атака · Ресурсы · Защита) сворачиваемых карточек
с цветовым кодом заголовка; строки «лейбл — значение» с семантическим цветом
значения; тулбар поиска + Компактно/Свернуть всё.

**Style Guide (для каждого варианта):** палитра (поверхности/текст/бренд/
семантика/стат/редкости/стихии), типографическая шкала, спейсинг+радиусы,
компоненты (кнопки primary/secondary/confirm/danger, чипы стат-HUD,
карточка-панель, строка-селектор, таб-бар/nav-rail, поле ввода).

## Отличия варианта B (смелые решения одобрены)

- **Вертикальный nav-rail** слева вместо верхних вкладок (иконка + подпись,
  активный — золотой индикатор).
- Тонкий золотой градиент / «гравировка» на брендовых элементах и заголовках
  карточек.
- Слоистые/текстурные поверхности, орнаментальные разделители в духе игровых
  тултипов.
- Расширенный стат-HUD: дельта-индикатор / мини-бар к числу.
- Может вводить новые CSS-переменные сверх базовых токенов (помечать как
  «B-only», т.е. потребует новых XAML-токенов при портировании).

## Техническая форма артефакта

- Один самодостаточный HTML-файл (инлайн CSS, без внешних зависимостей; шрифты —
  системные/Inter с фолбэком), путь: `docs/design/pblapp-restyle-mockup.html`.
- Верхний переключатель **A / B** (и dark/light, т.к. токены уже двутемные —
  опционально, dark обязателен).
- Каждый экран — статичный визуальный мокап (не функциональный прототип);
  кликабельность ограничена переключением A/B и навигацией по якорям секций.

## Вне рамок (YAGNI)

- Никакого изменения реального Avalonia/XAML-кода в этой итерации.
- Не охватываем: Дерево пассивок, Настройки, Заметки, Импорт/Экспорт, тултипы
  предметов (только если останется время — не обязательны).
- Не делаем функциональный JS-прототип с реальными расчётами.

## Критерий готовности

HTML открывается в браузере, переключатель A/B работает, оба варианта содержат
Style Guide + 4 экрана на реальном контенте, вариант A визуально доказуемо
собран только из базовых токенов.
