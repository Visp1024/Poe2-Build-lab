# Цифровая подпись сборок

Сейчас релизный `PBLApp.exe` публикуется **без подписи**. Windows SmartScreen
показывает «Windows защитила ваш компьютер» каждому, кто скачал сборку, и
чтобы её запустить, нужно нажать «Подробнее → Выполнить в любом случае». Для
публичного проекта это главный барьер на входе.

Ниже — почему бесплатных «сделай сам» вариантов больше не существует, какой
единственный бесплатный маршрут реально работает для опенсорса, и что нужно
сделать, чтобы им воспользоваться.

## Почему нельзя просто купить дешёвый сертификат и подписывать локально

С **1 июня 2023** правила CA/Browser Forum требуют, чтобы приватный ключ
сертификата подписи кода хранился на аппаратном носителе уровня FIPS 140-2 L2 /
Common Criteria EAL4+ — USB-токене или в облачном HSM. Файл `.pfx`, который
можно было положить в CI и подписывать чем угодно, центры сертификации больше
не выдают.

Следствия:
- «купить сертификат за $70 и подписать локально» — вариант закрыт;
- любой сертификат теперь идёт с токеном (курьером) или с облачной службой
  подписи, и это ежегодные деньги;
- **self-signed** сертификат бесплатен, но SmartScreen и «Неизвестный
  издатель» он не убирает вообще — цепочка доверия не строится. Смысла нет;
- **Sigstore / cosign** бесплатен и хорош, но Windows не доверяет ему для
  Authenticode: подпись будет, предупреждение останется.

## Бесплатный вариант для опенсорса: SignPath Foundation

[SignPath.io](https://signpath.io/) держит программу **SignPath Foundation** —
бесплатный сертификат подписи кода и бесплатный сервис подписи для проектов с
открытым исходным кодом. Это тот самый бесплатный маршрут, и в экосистеме .NET
им пользуется большая часть заметных OSS-проектов.

**Что уже подходит:**
- лицензия MIT — OSI-одобренная ✔
- открытые исходники — после публикации репозитория (задача #36) ✔
- продукт не содержит рекламы, майнеров и телеметрии ✔
- **сборка из CI** — есть: [`.github/workflows/release.yml`](../.github/workflows/release.yml)
  собирает релизный архив на `windows-latest` по пушу тега `v*`. SignPath
  подписывает только артефакты публичного CI и требует, чтобы они собирались из
  того же репозитория и коммита — это условие выполнено.

**Чего не хватает:** репозиторий пока приватный. Заявку можно подавать сразу
после того, как он станет публичным.

### Порядок действий

1. ~~Перенести сборку релиза в GitHub Actions~~ — сделано в задаче #36.
2. Открыть репозиторий (тоже #36).
3. Подать заявку в SignPath Foundation с формы на сайте: ссылка на репозиторий,
   лицензия, описание проекта, чем он полезен, ссылка на релизы.
4. После одобрения — завести в SignPath проект и signing policy, положить
   `SIGNPATH_API_TOKEN` в секреты репозитория и добавить в workflow шаг
   `signpath/github-action-submit-signing-request`.
5. Вставить шаг подписи в `release.yml` между «Publish» и «Create archive»,
   чтобы в архив попадал уже подписанный `PBLApp.exe`; из тела релиза убрать
   абзац про SmartScreen.

### Оговорка про репутацию SmartScreen

Обычная (OV) подпись — а SignPath Foundation даёт именно OV — **не снимает
предупреждение мгновенно**. SmartScreen накапливает репутацию издателя по числу
загрузок; первые сборки после подписи всё ещё могут ругаться, но, в отличие от
неподписанных, репутация начинает копиться на издателя и переносится на
следующие версии. Мгновенно предупреждение снимает только EV-сертификат,
бесплатных EV не бывает.

## Платные варианты, если SignPath не подойдёт

| Вариант | Цена | Что даёт |
|---|---|---|
| **Azure Trusted Signing** | ~$10/мес | OV-подпись из CI, ключи в облачном HSM Microsoft. Нужна верификация личности/организации: для юрлица — 3+ года истории, для физлица — отдельная процедура. Самый дешёвый платный маршрут. |
| **OV-сертификат** (Sectigo, DigiCert) | ~$200–400/год | То же доверие, что и SignPath, но с аппаратным токеном и своей вознёй с логистикой. Смысла поверх бесплатного SignPath нет. |
| **EV-сертификат** | ~$400–600/год | Единственное, что убирает SmartScreen сразу, с первой сборки. |

## Решение

**Маршрут — SignPath Foundation, заявка после открытия репозитория.** До
одобрения сборки остаются неподписанными; в описании релиза стоит явно предупреждать про SmartScreen и
указывать SHA-256 архива, чтобы скачавший мог проверить целостность.
